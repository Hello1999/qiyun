# 体验与设计方向

设计主题：轻盈的运维工作台。温暖、清楚、有呼吸感，让用户很快知道服务器的现状，并看懂 AI 正在做什么。

这是设计规范草案，尚未形成可运行界面或完成视觉验收。

## 1. 产品结构

主导航：概览、服务器、服务、操作记录、设置。巡检与自动化在 MVP+ 增加，不在首版摆放空功能入口。

资源是页面主体，AI 输入始终可达。进入具体资源后显示可编辑范围，例如“当前范围：web-01 / 博客”，提交前始终可见。多目标有歧义时要求选定资源，不能凭昵称猜测后执行。

桌面采用 216 px 导航、最大约 1440 px 内容区、8:4 主次列；宽度不足时收起侧栏，1024 px 以下单列。移动端重点支持状态查看、任务审批和结果查询。

## 2. 首页第一屏

从上到下：

1. 清楚的整体摘要：在线主机、健康服务、需要处理事项、最后更新时间。
2. 一条最值得关注的事件，带“帮我检查”和“查看服务”入口。
3. 宽阔的任务输入框：想查看什么，或需要我处理什么？附资源范围、麦克风和发送。
4. 三个真实快捷动作：检查运行状况、查找异常服务、查看最近操作。
5. 主列为服务卡片，次列为正在进行/最近完成的任务。

首屏不铺拓扑连线。服务详情再展示关联容器、HTTP 健康、资源趋势、日志、配置版本和动作入口。原型数据要标“演示”，不能伪装真实服务器。

## 3. 视觉系统

| Token | 浅色方向 |
| --- | --- |
| 页面底色 | `#F5F6F2` 暖雾 |
| 卡片 | `#FFFFFF` |
| 浮层 | `#FAFBF8` |
| 主文字 | `#202B29` 深墨 |
| 次文字 | `#5F6D68` |
| 分隔线 | `#DCE3DD` |
| 品牌/主按钮 | `#185C48` 深绿 |
| 轻选中背景 | `#E5F2EB` |
| 提醒 / 危险 / 信息 | `#A76213` / `#B84238` / `#366BA4` |

深色模式使用墨绿灰底和柔和文字，保留相同语义；具体 token 在组件实现时成套验证。颜色搭配图标和文字，不能单独表达异常。

中文优先系统无衬线字体，英文可用自托管 Inter，数字启用等宽数字，路径/差异用等宽字体。避免运行时依赖外部字体 CDN。

标题 28/36 px、区块标题 18/26 px、正文 15/24 px、辅助 13/20 px、关键数字 32/38 px。间距使用 4/8/12/16/24/32/48 px；卡片圆角 16 px、输入 12 px、按钮 10 px。

让留白、排版和反馈承担精致感；明显阴影仅用于菜单、浮层和对话框。避免满屏玻璃层、装饰性光晕、漂浮指标和持续流动背景。

## 4. AI 任务单

提交后打开任务侧栏，可扩展为独立任务页。保持一张持续更新的任务单，避免用大量对话气泡承载执行事实。

阶段：检查现状 → 给出建议 → 等待确认 → 执行操作 → 验证结果。每一步展示开始时间、状态、当前动作、证据展开入口。只展示可核验步骤与简要说明，不制作“内部思维直播”。

未知耗时显示“正在检查 · 已用 18 秒”，不用假百分比。并行检查可以显示“已完成 3/5 项检查”，不能将它包装为整个修复任务进度。

结论区固定回答：做了什么、哪些对象受影响、是否验证成功、剩余问题、是否能够恢复。部分成功必须单独标明。

## 5. 操作确认与差异

确认卡展示目标环境/主机/服务、拟执行动作、影响、前置检查、可恢复范围、验证方式。按钮写“确认重启博客”，而非“确定”。普通操作只有一次有意义的确认，不堆叠弹窗。

配置先展示易懂的字段变化，再展开完整 diff；秘密字段遮盖。审批后计划或目标状态改变时，明确解释变化并更新确认卡。

执行中区分“停止后续步骤”和“恢复已执行变更”。恢复不可用时说明具体原因，不放一个永远成功的回滚按钮。高风险且未实现的操作不显示可点击执行入口。

手动重启等按钮与 AI 任务使用同一套策略、审批、验证和审计链路，不能成为绕过路径。

## 6. 语音

点击开始/结束或按住说话；显示“正在听”、计时、轻量音量反馈、转写文本、取消与结束按钮。用户触发后才申请麦克风权限。

结束录音后保留可编辑文本，默认由用户提交。机器名识别不清时选择具体资源；语音表达不替代操作确认。播报默认关闭，原始音频默认不保留。

权限拒绝、无声音、网络中断、ASR不可用时，保留已经转写的文字和输入框。提供清楚的重试入口。

## 7. 动效规范

| 场景 | 时长与方式 |
| --- | --- |
| 按钮按下、悬停 | 100–140 ms，颜色/轻微缩放 |
| 菜单、状态变化 | 160–200 ms |
| 任务侧栏 | 240 ms，平缓减速 |
| 阶段变化 | 180–240 ms，局部切换 |
| 成功反馈 | 约 300 ms，一次图标变化 |

位移通常 8–16 px，仅解释内容出现和任务变化；不让数字不停跳动。使用 transform/opacity 优先，避免动画造成布局抖动。

`prefers-reduced-motion` 下关闭位移、弹性和闪烁，改为即时变化或 ≤100 ms 淡入。禁用动画后执行状态仍明确。

## 8. 必须设计的状态

| 状态 | 反馈 |
| --- | --- |
| 首次进入 | 接入引导、支持环境和明确标记的演示入口 |
| 未发现服务 | 说明发现/登记方式，避免无意义零值仪表盘 |
| 主机断线 | 保留最后数据和时间，连接中断不等于服务已停止 |
| 区块读取失败 | 局部重试，保留其余可用内容 |
| 执行失败/部分成功 | 已改变、失败、未执行分别列出 |
| 执行结果未知 | 显示“需要核对”，先检查实际状态，不引导盲目重试 |
| 模型不可用/限流 | 保留资产浏览、历史和策略内手动操作 |
| 权限不足 | 说明缺少哪类权限；不统一显示未知错误 |
| 刷新或重连 | 根据真实任务恢复，不重新提交 |
| 长时间等待 | 最后活动时间、检查和停止后续步骤入口 |

## 9. 设计验收

- 真实用户能在 10 秒内说出有哪些事项需要处理，此项通过可用性测试验证。
- 执行前能正确说出目标、环境、影响和恢复范围。
- 核心流程全键盘可达，焦点明确，对话框焦点管理正确。
- 主要触控目标至少 44×44 px；以 WCAG AA 对比度为目标，并实际检测。
- 200% 缩放和窄屏不遮挡关键操作；响应式重排不改变任务语义。
- 屏幕阅读器状态更新使用适度 live region，不逐条播报高频指标。
- 对浅色、深色、减少动画、空状态、断线和长文本分别进行截图/交互验收。
- 实现后的性能和真实数据状态优先于装饰；不能用设计稿验收代替运行界面验收。
