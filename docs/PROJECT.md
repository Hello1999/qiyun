# 项目状态与路线图 · 栖云 Qiyun

版本：首版工程 0.1；更新日期：2026-10-04。当前阶段为可运行首版与集成验收，已超出最初的方案定义阶段；尚不宣称生产就绪。

## 1. 项目是什么

面向 Linux 云服务器 / VPS 的自托管 AI 运维工作台，优先 Docker 容器与已登记 systemd 服务。资源界面呈现真实采集结果，AI 在限定工具范围内检查与提出建议，用户确认具体变更后才执行。

产品追求三个结果：看懂资源现状、明确控制变更、追溯任务过程。面向独立开发者与小团队，长期希望照看约 1–10 台 VPS；这仍是规模目标，不是已通过的容量验证。

## 3. 当前可以怎样使用

| 请求 / 操作 | 当前行为 |
| --- | --- |
| 看看这台机器有哪些服务需要关注 | 在所选范围内检查已有快照及日志，说明证据与采集时间 |
| 整理博客服务最近的报错 | 读取登记服务的有界日志并总结；不声称覆盖完整历史 |
| 重启博客服务 | 明确选择目标，生成影响、验证与恢复能力说明；批准后执行白名单重启 |
| 查看最近操作 | 查看任务过程、确认状态、工具结果及失败 / unknown 信息 |
| 网站打不开，帮我查原因 | 可从已采集容器 / 服务状态和日志调查；没有主动 HTTP / TLS 探测，不能据此宣称业务恢复 |

以下请求属于后续能力：修改内存限制、更新镜像版本、发布 Compose、恢复昨天配置、数据库回滚、定时巡检、自动修复。界面不提供假执行或假恢复按钮。

## 4. 操作边界

- 查询与诊断限于已授权、已登记目标及有界数据。
- 重启是当前唯一写动作。手动入口与 AI 建议共享同一策略、审批、版本检查和验证链路。
- 配置修改、镜像更新与自动修复尚未实现，不能由模型建议直接扩展权限。
- 不提供任意 Shell、任意路径写入、数据卷删除、数据库迁移或 SSH / 防火墙 / 权限变更。
- 停止请求不等于撤销已经发生的重启；无法确认结果时保留 unknown，并核对现实状态。
- helper 的权限边界不代表能够抵抗可信控制端签名权限完全失陷。

具体部署与恢复限制见[运行与接入](RUNNING.md)和 [Agent 说明](../agent/README.md)。

## 7. 质量与产品目标

- 可理解：用户能快速定位需要关注的资源，并在批准前说明目标、影响和恢复范围。
- 可验证：成功来自工具结果与后置状态核对；unknown 不伪装为成功或可安全重试。
- 可访问：键盘、焦点、窄屏、200% 缩放、浅深主题与减少动态效果经过实测。
- 可部署：明确支持平台、可信证书、权限配置及备份恢复；测试不借用用户生产服务。
- 可观测：记录请求 / token 用量和失败原因，不伪造套餐额度与实际费用。
- 性能预算：首屏可交互 ≤ 2 秒、交互反馈 ≤ 100 毫秒、通常状态新鲜度 ≤ 15 秒，均为待在声明条件下测量的目标。

长期方向仍是让少量服务器的日常照看更轻松。是否开源、许可证、商业化、团队规模与自动化程度尚待决定，不在当前首版加入未经验证的承诺。
