# 技术架构

这是实施基线草案，不表示以下组件已存在。

## 1. 分层与选型

| 层 | 暂定技术 | 职责 |
| --- | --- | --- |
| Web | React + TypeScript + Vite，Tailwind，Radix，Motion | 服务视图、文字/语音入口、计划卡、任务时间线 |
| 控制端 | Node.js + TypeScript + Fastify | 身份验证、资产、策略、模型适配、任务编排、审计 |
| 数据 | SQLite WAL + 版本化迁移 | 单实例资产、任务、审批、事件和短期采样 |
| 主机 Agent | Go，systemd，独立可执行文件 | 采集、持久化任务收据、执行与主机侧复核 |
| 特权执行器 | 最小 Go helper，Unix socket | 白名单 Docker/systemd 动作及受管配置应用 |
| 模型 | Ark Provider 适配器 | DeepSeek 工具调用、流式响应、限额与错误映射 |
| 语音 | 独立 ASR 接口 | 音频转文本，后续可选 TTS |
| 发行 | OCI 控制端镜像、Agent 平台包、发布清单 | 校验、版本兼容、健康检查、升级与恢复 |

先用显式状态机和持久任务表实现编排；暂不引入分布式工作流平台、消息中间件或多个数据库。技术栈的具体版本在初始化工程时锁定并验证，不能直接依赖浮动 latest。

数据路径：浏览器 → 控制端 → 模型与策略 → 持久任务 → 主机 Agent → 执行器 → Docker/systemd。模型只产生候选计划，不持有主机凭据或执行权限。

## 2. 部署与连接

单机起步允许控制端和 Agent 同机；控制端容器不挂载 Docker socket、不获得宿主 root。Agent 采用普通用户运行，通过受权限约束的本地 helper 执行必要动作。

helper 的 Unix socket 仅允许指定 Agent 身份访问，并校验对端进程凭据（如 SO_PEERCRED）。本机可操作资源和动作白名单由管理员保护，Agent 不能自行扩展。控制端签发短期任务授权，绑定 host_id、step_id、工具版本、参数/计划 hash、到期时间和防重放标识；Agent 与 helper 均验证签名及本机白名单。

mTLS 证明连接身份，不替代动作授权。如果控制端及签名能力被攻陷，攻击者仍可能在本机允许范围内发起动作；该设计限制影响范围，不能声称抵抗可信控制端完全失陷。更强的独立审批签名属于后续增强。

Agent 主动出站连接控制端：第一版 HTTPS 长轮询领取任务、批量回传事件；注册后使用 mTLS，证书绑定 host_id，可轮换、过期和吊销。Agent 不暴露公网管理端口。

一次性配对令牌短期有效，建立主机身份前核验控制端身份。UI 展示主机与证书信息。令牌通过交互输入等方式传递，不放入持久命令行、日志或安装链接查询串。SSH 可作为未来安装辅助，不是运行时任意命令通道。

首次控制端启动默认为本地访问与一次性管理员初始化；公网访问须启用 HTTPS 和身份验证。浏览器使用 HttpOnly、Secure、适当 SameSite 的会话 Cookie；校验 Origin/CSRF，限制登录尝试。主机通道与浏览器 API 分离。

单机控制端不可用时没有外部告警能力；将控制端放到独立主机和外部探针属于后续可用性方案。

## 3. Agent 工作流

运行时职责分为观察、规划、策略判断、执行和验证。首版只有一个规划调用链；读工具可有限并行，写步骤按资源锁顺序执行。

研发可由多位 Astra 子代理分担产品、前端、后端和评审。产品运行时默认使用用户选择的 DeepSeek，不自动依赖 Astra；多代理运行时必须证明收益后才引入。

每次任务依次进行：

1. 解析请求和主机/服务目标；歧义未消除前不产生写任务。
2. 获取必要实时证据，给数据加来源、采集时间和新鲜度。
3. 生成结构化计划，包括前置条件、动作、影响、验证、恢复能力。
4. 确定性策略引擎校验权限、目标、工具参数、风险、预算。
5. 必要时确认；审批绑定操作者、计划 hash、目标、参数、有效期。
6. 下发固化任务；Agent 与 helper 再校验能力和参数。
7. 执行前检查状态是否漂移，执行后进行健康验证并持久化结果。

模型不参与授权决定，不得修改策略。不能把模型的自评或另一位模型的“安全判断”作为执行边界。

## 4. 工具契约

每个工具包含 name、version、input/output JSON Schema、required_capabilities、risk_class、timeout、输出限制、重试语义、验证方法和恢复能力。

首批候选工具：`host.metrics.read`、`services.list`、`service.logs.read`、`website.probe`、`container.restart`、`systemd.restart`。配置更新工具在 P3 单独实现。

所有输入运行时校验，未知字段拒绝。目标来自登记资源 ID；日志窗口和字节数有上限。执行使用固定程序路径和独立 argv；不拼接 Shell、不提供通用 shell.exec。

网站探测只访问已登记目标，防止把用户输入变成任意网络访问；限制重定向、DNS 解析目标、请求体、超时，拒绝云元数据地址和未经授权内网目标。确需内网站点时由管理员明确登记允许网段。

受管 Compose 操作仅允许已审批字段；原文件不能偷偷夹带新的 privileged、宿主敏感挂载、capabilities、设备或任意 hook。先解析、策略校验，再运行 Compose 验证。只读导入现有项目不等于授权其整体重新部署。

审批绑定完整解析后的有效配置和所有输入依赖摘要，包括环境变量、覆盖文件及 include/extends。执行使用已验证的固化输入；相关依赖变化则旧审批失效。helper 在校验至应用期间持有资源锁，并避免可替换路径造成检查与执行不一致。首版不支持无法固化的外部依赖。秘密值参与私有完整性校验，但不进入公开计划、diff、Git 或日志。

Docker group/socket 具有宿主高权限，应只置于可信执行器边界。[Docker 官方说明](https://docs.docker.com/engine/install/linux-postinstall/)

## 5. 状态与断线语义

任务主要状态：`observing → planned → awaiting_approval → queued → running → verifying → succeeded`。

终止分支包括 `rejected`、`expired`、`failed`、`cancelled`；无法判断是否已产生副作用时进入 `unknown`，先核对现实状态。只读任务可跳过审批，但仍经过策略。

- 每个 task/step 使用持久唯一 ID，事件使用递增序号；重连按游标补传。
- 网络采用至少一次投递；Agent 本地收据去重。资源写操作有锁和租约版本/fencing 检查，旧执行者不能在锁转移后继续新写操作。
- 不承诺跨崩溃边界严格 exactly-once。重启不是天然幂等，回执丢失不能直接再重启。
- 租约过期先核对 Agent 收据与主机状态，不自动复做有副作用的步骤。
- `cancel_requested` 是事件，只有确认停止或从未执行才能标记 cancelled；无法中断的步骤完成后阻止后续步骤。
- 浏览器断开后任务按已批准范围继续；模型超时、预算耗尽或后续计划变更都不能扩大范围。

## 6. 数据与审计

核心实体：Host、Service、Observation、Conversation、Task、TaskStep、Plan、Approval、Policy、AuditEvent、ManagedConfigRevision、ProviderProfile。

审计保存：用户请求、依据引用、固化计划、策略版本、审批者、工具/执行器版本、实际参数、前后状态摘要、退出码、脱敏输出、验证结果与配置 revision。内部保存 UTC，页面按用户时区显示。

日志和配置按需截取、脱敏后才发送外部模型；原始音频默认处理后删除，不默认保存完整会话音频。模型内部推理文本不作为必须持久化的审计材料，UI 展示可验证的步骤与依据。

本地审计数据库可以被主机管理员修改，不宣称防篡改。后续需要独立审计存储与外部校验锚点。指标先保留有限窗口，容量与保留周期可配置；不替代专业时序数据库。

## 7. Git、恢复与备份

源码仓库版本化代码、契约、策略模板、部署模板、文档。每台主机的受管配置位于独立私有配置库，只收录白名单文件与秘密引用，不复制完整 /etc 或 .env。

配置库 revision 与任务关联。应用前记录原内容、文件权限、目标 hash、固定镜像 digest。发现外部修改先生成新差异，旧审批作废。

恢复是新的受控任务。Git revert 只生成配置差异，并不代表服务器已经恢复。恢复旧镜像不恢复数据库和卷数据；涉及数据迁移的更新首版拒绝自动执行。无已确认数据兼容性时不能自动降级镜像。

SQLite 备份使用一致性快照/在线备份机制，不能运行中只复制主 .db 文件忽略 WAL。真实备份与恢复演练独立于 Git；密钥备份需要另行安全管理。

## 8. 模型与成本

Provider 接口隔离 model id、base URL、协议、工具能力、thinking 参数、上下文/输出限制与供应商错误。优先验证 Chat Completions 工具链；不假定兼容协议等于所有参数都可用。

为单任务设置模型请求次数、工具步数、超时、并发和 token 预算；请求前检查输入规模、显式限制输出并累计可观测用量，预算到达由编排器停止扩展任务。日常遥测和规则判断无需每次调用模型。429 使用有界退避，鉴权失败停止重试；请求重试不得重放已执行写工具。

Coding Plan 的 token 数不直接等于单任务账单金额。分别记录 API 返回用量、可观测的套餐额度消耗，以及明确标为估算的套餐费用分摊。无可靠数据时金额/额度显示不可用，不伪造精确费用；强制上限以可执行的调用、token、并发和时间规则为准。

运行时凭据由服务端配置/秘密存储提供，不进入浏览器、源码、命令行或普通日志。方舟接入尚未实测，见 [接入核查](ARK-INTEGRATION.md)。

## 9. 安装、升级与版本

一行安装是发布阶段的交付目标。现阶段不发布占位 curl 命令或虚构下载地址。

安装器依次进行环境/架构/端口/权限检查、版本选择、下载校验、安装 Agent 与控制端、管理员初始化、配对、健康检查。缺失 Docker 时明确说明依赖安装，不无提示更改现有 Docker。

发布清单包含版本、平台、哈希、签名、协议兼容范围与迁移要求。签名公钥必须有独立可信来源；随未验证安装包下载一个公钥不构成独立信任。bootstrap 的 HTTPS 来源和信任方式需公开，不能把单行脚本描述成天然可信。

升级前备份配置和数据库，检查迁移可逆性，固定镜像 digest；关键任务执行时不替换 Agent。健康检查失败可恢复旧二进制/镜像，破坏性数据库迁移不能承诺自动回退。卸载默认保留用户数据与受管服务。

代码使用 `codex/<topic>` 分支、语义化提交、经过验证后打 SemVer 标签。具体远程托管和发布签名方式待仓库建立后选择；本轮没有 push 或发行。
